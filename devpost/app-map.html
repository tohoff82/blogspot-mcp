Draft-Only Blogger MCP

A local stdio MCP server that can create one private draft in one configured Blogger blog, or inspect a known draft. It verifies the Blogger projection and durable provenance through separate evidence paths, without exposing publication authority.

The externally inspectable authority boundary

create_draft

One bounded effect path

Validates an authored projection, makes at most one private-draft insert attempt, then verifies what can be established.

inspect_draft

One read-only proof path

Reads a known post and compares Blogger projection facts plus sidecar provenance with independently supplied expectations.

Structurally absent

No publish, update, delete, schedule, target-selection, generic Blogger request, or provenance-repair tool is registered.

Fixed operating boundary

The blog target comes from operator configuration. Draft state is not caller-selectable, and uncertain creation is never retried blindly.

Create action and independent proof path

  1. Validate Reject malformed authored projections before Blogger is contacted.
  2. Insert once Attempt at most one Blogger draft creation with draft state fixed.
  3. Persist provenance Store artifact and version identity under the known blog and post key.
  4. ADMIN read-back Read the created post even if provenance persistence failed.
  5. Re-read sidecar Establish provenance from committed storage, not the create receipt.
  6. Verify and classify Preserve six MATCH, MISMATCH, or UNKNOWN results.

Fail-closed boundary: if the insert effect is unknown, return REMOTE_EFFECT_UNKNOWN with retry_safe: false, write no speculative provenance, and stop.

Blogger is projection truth

ADMIN read-back establishes configured target, DRAFT state, title, canonical body, and exact label set.

The owner sidecar is provenance truth

A committed, independently re-read record establishes artifact and version provenance. It cannot override Blogger facts or grant publication authority.

To change this, start here

Tool names, descriptions, or schemas

Start at src/server.ts and the contract schemas it imports. Any new tool would change the authority surface and requires architecture approval.

Create ordering or retry semantics

Start at src/tools/create-draft.ts. Preserve the one-insert boundary and the stop on unknown remote effect.

Material comparison rules

Start at src/domain/verify.ts, then verify classification precedence in the outcome helper and tests.

Provenance persistence safety

Start at src/provenance/sidecar-store.ts. Treat non-overwrite, locking, atomic replacement, and re-read as one contract.

A practice to reuse

Design both the effect path and the independent proof path.

This project first tested Blogger customMetaData as durable provenance. The live gate showed that the tested contour did not provide the required reliable round trip. The localized R1 repair kept Blogger as projection truth, moved only provenance truth to the owner-controlled sidecar, preserved the two-tool surface, and retained MATCH / MISMATCH / UNKNOWN evidence plus fail-closed retry semantics.

On another project, use the same move: when live evidence invalidates one proof mechanism, repair the smallest affected boundary without widening authority, weakening verification, or rewriting the failed evidence.

Run it again safely

Use Node.js >=24 <25. Keep all four configured paths external to the repository and follow the current README.

node --version
npm ci
npm run build
npm test
BLOGGER_LIVE_TEST=0 npm run test:live

# After external configuration and OAuth readiness:
npm run auth
npm start

No live effect is implied: do not run BLOGGER_LIVE_TEST=1 npm run test:live without separate, explicit authorization for exactly one Blogger draft create attempt.
